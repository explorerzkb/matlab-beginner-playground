# 《🍐湖搭子》设计理由与第一次自我审查

更新日期：2026-09-03

状态：**早期弹性连接方案的历史自审，不代表当前玩法。** 本文解释产品方案 v0.1 当时为什么这样设计、哪些要求曾被认为已经满足、哪些仍然只是推断。后续讨论已经重新打开双人角色、核心物理、空间结构和局制；当前状态见[游戏方案默认假设审计 01](assumption-audit-01.md)。

## 一、先给结论

《🍐湖搭子》目前是一个**结构上值得验证、但尚未证明好玩**的候选方案。

它已经较好满足以下要求：两个人共同操作、一局 2—4 分钟、没有怪物和死亡、物理规律直接进入手感、校园元素近期且容易识别、MATLAB 初学者能够运行和解释、Windows 普通核显电脑能够承载。

它只部分满足“让人眼前一亮”。弹性绳连接双人角色并不是从未出现过的游戏机制；如果 MATLAB 只在开场画一条曲线、结尾再画一次曲线，中间仍是普通横版过关，那么作品会退化成“北理工贴图版双人平台游戏”。这正是下一步必须解决的问题。

因此，当前设计需要把真正的结构性反转明确为一个闭环：

> MATLAB 数据变成校园世界 → 两位玩家在世界中留下运动轨迹 → 轨迹重新成为 MATLAB 数据 → 数据改变下一段世界。

只要这个闭环在实际游玩中可见，MATLAB 就不是启动游戏的外壳，北湖也不是随意选择的背景。

首版应当至少实现一次局部闭环：玩家破防后，破防前最后一小段轨迹被降采样为少量线段，并在当前 100 米小段凝固成可以踩踏的“错误解曲线”。它只负责让下一次尝试略微容易，正常路线仍然允许一次通过，因此不是要求玩家故意失败的谜题。跨多局永久积累仍然属于后续功能。

## 二、为什么选择北湖

选择北湖不是因为“校园游戏总得找一个地标”，而是因为它同时解决了空间、节奏、文化识别和数学表达四个问题。

### 1. 北湖可以容纳多个校园元素而不显得像展板

鹅、黑天鹅、跑步环线、桥、水面和动物学长都可以自然出现在北湖附近。若把场景放在一间教室，校园网、破防水、鹅和桥只能被依次搬进来，容易像梗的陈列柜。

### 2. 1000 米环线天然提供关卡刻度

北湖约 1000 米的环线和每 100 米标记可以直接变成关卡进度、检查点和短局分段。首版只走 300 米，不需要伪装成真实比例地图。玩家理解“走到下一个 100 米标记”不需要阅读教程。

### 3. 环湖路线可以与 MATLAB 曲线建立真实联系

一条封闭路线可以在 MATLAB 中表示为一组坐标；玩家的位置、速度和历史轨迹也都是数组。开场的 `plot` 曲线变成道路，结尾的运动重新变成曲线，二者不是纯粹视觉相似，而是同一批坐标数据在“图”和“游戏世界”之间切换表达方式。

### 4. 北湖有平静、日常的初始气质

“正常北湖逐渐被 MATLAB、校园网和期末任务侵入”比一开始就在怪异世界中更容易形成反差。先让玩家确认现实，再逐步破坏现实，意外才有落点。

北湖也存在风险：`10.0.0.55`登录页和期末任务并不属于真实北湖地理。游戏必须从一开始说明这是“MATLAB 根据校园记忆画出来的北湖”，而不是校园导览模拟器。否则任何元素都掉到北湖里，会显得只是为了方便串梗。

## 三、为什么用两个被连接的角色

最初要求是至少两个人共同玩。最容易犯的错误是做两个互不影响的角色：两人只是在同一屏幕分别跑，合作停留在口头层面。

弹性连接被选中，是因为它能建立一条立即可见的因果链：

> 一人加速或跳跃 → 连接被拉伸 → 弹力改变另一人的速度 → 另一人必须接住、借力或反向补偿。

它同时具有四个优点：

- 双方始终互相影响，合作不是可有可无的附加要求；
- 拉过头、被同伴拽回和两人一起弹飞会自然产生肢体喜剧；
- 重力、摩擦、速度、弹力和阻尼都能被玩家感受到，不需要先打开参数面板；
- 物理模型可以用大学物理和基础数值积分解释，不需要完整专业力学课程。

但它也有三个明确缺点：

- 类似“被绳连接的双人闯关”已有成熟游戏，因此连接本身不承担全部创新；
- 弹力参数稍有不当就会从“好笑的失控”变成“无法控制的抖动”；
- 两个角色互相拖累可能引发真实争吵，必须用短检查点、快速重来和温和失败降低挫败感。

因此，弹性连接只能通过 30—60 秒灰盒原型证明价值。若两位玩家在没有校园美术的情况下不会笑、不会互相喊话或不会主动再玩一次，就应当换机制。

## 四、为什么从键盘加鼠标改为双键盘

上一版把“一人键盘、一人鼠标”当成不对称合作的创新点。用户指出，很多人不会随身带鼠标；让第二个人使用笔记本触控板还会与第一位键盘玩家争抢桌面和手部空间。

从产品角度看，这个现实摩擦大于输入方式的新奇。因此当前建议改为：

- 默认两人都使用同一把键盘；
- 玩家一使用 `A/D/W`，玩家二使用方向键，具体组合在目标笔记本上测试；
- 每位玩家同样控制水平施力和跳跃，角色能力对等；
- 键盘加鼠标保留为可选实验模式，不作为课程演示依赖。

双键盘降低了首次理解成本，也更符合“大家围着一台电脑立刻开始”的场景。代价是失去输入设备带来的不对称感，所以作品的意外性必须来自世界结构和数据闭环，而不能继续依赖“一个人竟然用鼠标控制角色”。

同一笔记本键盘可能存在“鬼键”：某些多个按键组合无法同时被硬件识别。解决方法不是假定现代电脑一定没问题，而是：

- 游戏不要求每位玩家同时按住三个键；
- 提供 `WASD + 方向键`和 `WASD + IJKL`等可切换方案；
- 在开始界面做一个五秒双人按键检测；
- 在正式演示电脑上实测最常见的同时移动和跳跃组合。

## 五、三个场景为什么按这个顺序

三个事件不是按“哪个梗最火”排序，而是构成从正常现实逐步失控的三层推进。

### 第一层：物理校园——鹅学长

鹅是现实中会移动、会占路的校园居民。它先帮助玩家认识北湖，也承担操作教学。鹅只改变道路边界，不攻击角色，所以符合“没有怪物”的偏好。

这一段必须最容易，让玩家先体验“我拉你过去、你把我接住”的快乐。如果教学段已经频繁破防，后面的文化表达没有意义。

### 第二层：数字校园——`10.0.0.55`

登录界面本来属于屏幕，却突然具有质量、重力和碰撞，掉进校园世界。这是第一处明显的规则破坏，也是最接近“MATLAB 窗口和游戏世界互相吞噬”的场景。

登录框不能只是背景截图。它必须成为会下落的平台，红色提示必须成为横梁，玩家才能通过动作理解“数字界面物理化”。

### 第三层：心理校园——任务风暴与破防水

最后侵入世界的不是动物或系统，而是学生自己的未完成任务。玩家无法消灭任务，只能共同取得破防水，把混乱暂时减速。这既避免传统战斗，也把个人压力转换成共同仪式。

三段合起来形成：

> 熟悉的物理校园 → 数字系统侵入现实 → 心理压力侵入数字世界 → 玩家把整个过程重新记录为一条 MATLAB 曲线。

这条因果线比“鹅、登录页、饮料三个梗依次出现”更重要。如果制作时看不出这条升级关系，就应当删掉或重写中间场景，而不是增加第四个梗补救。

## 六、为什么一局是三个 100 米段

用户要求最小游戏单元不超过五分钟，30 秒也可以。三个 100 米段能够提供最小的起承转合：

- 第一段学习共同操作；
- 第二段看见世界规则第一次明显破裂；
- 第三段在更大压力下使用已经学会的合作方式；
- 结算把动作转回数据。

两段很难形成升级，五段以上又会让首次展示过长、校园梗互相稀释。2—4 分钟允许课堂上失败后立刻再玩一局，也允许两位玩家互换位置重新尝试。

## 七、它如何满足“MATLAB 初级入门程序”

“入门”不等于所有代码必须塞在一个脚本里，也不等于作品只能使用循环画抛物线。它应当让学生能够沿一条清楚的路径理解程序：

1. 输入回调记录两位玩家按了什么；
2. 游戏循环根据输入更新速度和位置；
3. 碰撞函数阻止角色穿过地面；
4. 弹性连接根据两人距离计算相互作用；
5. 渲染函数把状态画到 `figure`窗口；
6. 关卡数据决定这一段出现什么物体；
7. 最后把记录的位置数组交给 `plot`画成曲线。

这些内容对应变量、数组、条件判断、循环、函数、结构体、绘图和事件回调，足以构成 MATLAB 基础的整体认识。Symbolic Math Toolbox 只在开场求解一次简单常微分方程，不能支配整个项目；否则学生会误以为游戏的主要价值是调用一个高级函数。

## 八、逐项审查最初要求

| 最初要求 | 当前满足程度 | 依据或缺口 |
| --- | --- | --- |
| 至少两人共同玩 | 较好满足 | 两位玩家通过弹性连接持续互相影响 |
| 一局不超过五分钟 | 满足 | 三个 100 米段，目标 2—4 分钟 |
| 不是谜题或参数演示 | 满足 | 连续操作、即时反馈，不要求停下来计算答案 |
| 对普通人有趣 | 尚未证明 | 物理失控和合作可能有趣，但必须由灰盒试玩验证 |
| 眼前一亮、打破预期 | 部分满足 | 数字界面物理化和数据闭环有潜力；单独的弹性双人机制不新 |
| 没有怪物和死亡 | 满足 | 鹅是移动边界，失败称为破防并快速回到检查点 |
| 有力学入门感觉 | 较好满足 | 重力、摩擦、惯性、弹力和阻尼直接改变手感 |
| 不必一眼看出物理 | 满足 | 先玩，结算或讲解时再揭示模型 |
| MATLAB 初学者能接触基础 | 满足方向，待代码验证 | 数据流清楚，但最终文件数量和函数边界仍需控制 |
| 北理工元素一眼能懂 | 较好满足 | 北湖鹅、登录页和破防水均保留具体视觉锚点 |
| 视觉和素材方便修改 | 满足方向，待实现验证 | 配置、关卡、图片和音频计划分离 |
| 普通 Windows 笔记本可运行 | 规格上满足，尚未实测 | 2D 图形预算较低，最终仍以 Windows 实机为准 |

最需要诚实保留的两个“尚未证明”是：**它是否真的好玩，以及数据闭环在游玩中是否足够明显。**这两项不能靠继续写设计文档证明。

## 九、下一步应该验证什么

在继续画校园场景之前，只做一个 30—60 秒灰盒：两个简单圆形角色、双键盘、弹性连接、两块地面和一个小坡。试玩时观察四件事：

1. 两个人是否会自然地互相提醒、责怪和救场；
2. 失败后是否愿意立刻再试一次；
3. 不解释弹簧公式时，玩家能否从手感中学会借力；
4. 去掉北理工美术后，这个核心是否仍然有最低限度的快乐。

只有这四项成立，才继续制作鹅学长和校园网。若核心不成立，下一轮应比较“共同搬运不稳定物体”“两人控制同一条可变曲线”和“分处两个坐标系但共享一个物体”等备选机制。
