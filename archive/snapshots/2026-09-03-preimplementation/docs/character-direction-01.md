# 双人角色方向 01：从 MATLAB 数据点长成的“梨点”

## 已确认的角色类型

2026-09-03，用户从“可爱小生物型”“校园新生型”和“抽象表情包型”三个方向中明确选择了**可爱小生物型的小🍐**。两名玩家角色应是同一物种、同一体型、同一能力和同一套动画的原创梨形小生物；不采用写实大学生、“梨头人”或以服装细节为主体的校园新生造型。

“角色最初是 MATLAB 曲线上的两个数据点，图形界面发生异常后落出坐标轴并长成小🍐”仍是推荐的出场叙事，不因角色类型得到确认而自动成为最终设定。工作称呼“梨点”也不是最终角色名。

这个方向可以把三个部分接在一起：开场的 MATLAB 图、“🍐”这一北理网络表达暗号，以及适合表现重心、拖拽、压缩和摆荡的梨形轮廓。其中，采用可爱梨形小生物已经确认；具体怎样从 MATLAB 界面进入游戏世界仍需随后敲定。

## 外形规则

- 两个角色的外轮廓、碰撞体积、视觉重量和动画时长完全相同，玩家不会从外形误判一方更强、更重或跳得更高；
- 身体上窄下圆，但底部不能太宽，否则跑动时像滚动水果，绳子拉紧时也不容易看出身体朝向；
- 四肢短而有力，手臂必须能清楚表现抓、撑、拉和挂，不能使用只有一条线的火柴人手臂；
- 头顶保留一个很小的“数据柄”或叶片形标记，让它同时像数据点的指示柄和抽象梨梗；
- 面部先采用两个点眼和一条简单嘴线，把情绪主要交给身体前倾、挤压、拉长和四肢姿势；
- 腰部设置一个简洁连接环，普通绳连接在环上。这个结构解释了绳力作用的位置，也避免绳子看起来拴在脖子上；
- 轮廓使用深海军蓝或近黑色描边，在蓝天、湖水、浅灰建筑、花海和登录页上都保持可读。

## 两名玩家如何区分

玩家一使用暖梨黄或琥珀色，胸前是实心圆点；玩家二使用湖水青或蓝色，胸前是实心菱形。颜色负责快速分辨，圆点与菱形负责在色觉差异、投影偏色和黑白截图中继续分辨。两者没有不同能力，也不使用暗示职业、性别或力量差异的服装。

键位提示、角色头顶短暂出现的玩家编号和暂停界面中的图标，都必须同时使用“颜色加形状”，不能只依赖红蓝或黄蓝。

## 绳与动作

绳子仍然是普通绳：松弛时弯垂，达到长度上限后传递拉力；它不缠绕、不打结、不断裂。两个腰环是绳的唯一固定点。

第一版至少需要六类动作状态：

1. 跑动；
2. 起跳、上升和下落；
3. 绳子拉紧时前倾用力；
4. 被队友拖拽时脚底滑动；
5. 悬挂在平台边缘或绳下；
6. 两人配合摆荡。

动作可以使用夸张的挤压与拉伸来增加喜剧感，但视觉变形不能改变物理碰撞盒，否则玩家会看到身体碰到平台却仍然穿过，或看似没碰到却被挡住。

## MATLAB 中的轻量实现

角色建议使用带透明通道的 PNG 精灵图。两名角色共用 16—24 张基础动作帧，程序加载后通过色彩替换或两套导出图进行区分。游戏中角色显示高度约 90—120 像素；碰撞使用简单的圆角矩形或胶囊形区域，而不是按图片轮廓逐像素检测。

这种做法只需要切换图片帧、位置和旋转角度，不需要三维模型、骨骼系统、实时布料或复杂光照，适合 MATLAB 二维图形系统和目标 Windows 电脑。最终帧数仍需由灰盒动作速度和实机帧率决定，当前数字是实现预算，不是已经验证的性能结论。

## 为什么不优先用校园动物当双主角

鹅、羊驼和孔雀适合成为校园里的学长、路人或短暂事件，但不适合直接组成这对能力相同的玩家角色。三种动物的身体结构、步态和体重印象差异太大，观众会自然预期它们拥有不同能力；绳子连接动物还容易被看成牵引绳或拴宠物，削弱“双人互相救援”的关系。

即使使用两只鹅，翅膀、长颈和短腿也很难清楚表现抓平台、撑住队友和摆荡。使用普通人类学生则过于常规，而且会把画风拉向此前已经失败的写实校园插画。纯公式或纯几何点虽然与 MATLAB 联系最直接，却难以承载身体喜剧和情绪。因此，“同物种的梨点为玩家，校园动物为世界角色”是当前最平衡的分工。

## 仍待视觉样张回答的问题

以下内容尚未确认，不能写入最终美术规范：

- 梨的暗示是非常克制、第一眼像原创数据生物，还是让良乡学生立即认出“🍐”；
- 可爱感更偏圆润温和，还是偏淘气、具有更强的身体喜剧；角色不需要通过书包、校园卡等配饰明确扮演大学生；
- 眼睛采用最简单的点眼，还是更有网页小游戏味道的白色眼球；
- 身体表面是纯色平涂、轻微像素质感、漫画纸纹，还是与 MATLAB 网格融合。

下一步最有效的验证不是继续写设定，而是在完全相同的尺寸、姿势和绳连接方式下制作五组角色剪影。只比较轮廓、脸、腰环和梨形暗示强度；校园背景保持空白，避免场景再次干扰角色判断。
