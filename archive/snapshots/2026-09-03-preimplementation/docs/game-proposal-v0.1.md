## 一、当前产品结论

建议采用工作名《🍐湖搭子》。北理工学生在网络交流中常用“🍐”指代北理，这是用户提供并确认的校园用法；它将成为游戏的主视觉符号。考虑到 Windows 和不同 MATLAB 版本不一定能稳定显示彩色 Emoji，正式画面不直接依赖系统字体中的 `🍐` 字符，而是使用项目自带的梨形图片或 MATLAB 图形对象绘制梨形标志。

游戏的核心不是“北理工梗大合集”，而是一款两人通过同一物理系统紧密合作的横向游戏：

- 两位玩家默认共用一把键盘，分别控制一只受重力、摩擦和惯性影响的“小梨”；
- 两只小梨由一条具有弹性和最大长度的“搭子绳”连接。玩家需要利用拉伸、回弹、支撑和摆动共同前进；
- 每局沿北湖完成约 300 米的虚构短环线，经历三个相互独立的校园事件，用时约 2—4 分钟；
- 角色不会死亡。坠落、绳子过度拉伸或长时间卡住称为“破防”，两人回到最近的 100 米标记；破防前最后一小段运动轨迹会在当前小段凝固成可踩的“错误解曲线”，让下一次尝试略微容易。

这套结构把三类价值放在不同层次：

1. **持续乐趣来自两人共同控制一个弹性系统。** 即使去掉所有校园梗，拉、甩、接住同伴和意外回弹仍然可以形成操作乐趣。
2. **第一层惊喜来自 MATLAB 作业变成游戏。** 开场是一张普通的常微分方程解曲线；点击运行后，曲线逐渐变成北湖路线，曲线上的两个数据点变成两位玩家。
3. **校园认同来自少量、清楚的现实元素。** 一段路只出现一个主要校园梗，让北理工学生不经过解释就能认出它。

## 二、为什么选择这个方案

此前的候选创意中，“北湖短循环”“鼠标与键盘分工”“两人是同一条绳的两端”“MATLAB 坐标系吃掉校园”和“失败留下道路”可以合并为一条稳定的产品主线。其他创意不再平行发展为独立游戏。

这个方案相对传统跑酷或双人平台游戏多了两个可感知的差异：

- 两位玩家不是两个互不相干、分别跑到终点的角色；一方的动作会通过弹性连接立即改变另一方的速度和位置。
- 开场的 MATLAB 数据会变成校园世界，玩家在世界中的运动又会重新变成数据并影响后续画面。意外性来自这一结构闭环，而不再依赖键盘和鼠标的输入差异。

它也比“调节质量、刚度和阻尼后看曲线”的力学演示更接近游戏。质量、速度、力、摩擦、弹性和能量并不作为需要背诵的参数出现，而是成为玩家能直接感受到的操作后果。

## 三、一局游戏的实际过程

### 1. 开场：一份看起来很普通的 MATLAB 作业，约 10 秒

程序显示一个简化的常微分方程和一条解曲线。玩家点击“运行”后，坐标轴刻度变成北湖的 0、100、200、300 米标记，曲线变成道路，两个数据点落到路面上并展开成两只小梨。

如果电脑安装了 Symbolic Math Toolbox，程序可以在开场真正求解一次简单方程；如果没有安装，则读取项目中预先保存的相同结果。无论工具箱是否存在，核心游戏都能运行。

### 2. 0—100 米：鹅学长借道，约 35—55 秒

玩家先在正常北湖场景中学会移动、施力和利用搭子绳。随后一队鹅按队形横穿道路，形成不断移动的边界。鹅不会攻击玩家，也不能被击败。两位玩家需要一人站稳、一人借绳摆过道路，或者共同等待一个合适空隙。

这一段只表达“北湖鹅学长”，不同时塞入校园网、艾比特和破防水。

### 3. 100—200 米：怎么游戏里也要登录，约 35—55 秒

北理桥附近突然落下一张带有 `10.0.0.55` 的校园网登录界面。登录框成为有质量、会下落的移动平台；页面上方的红色保密提示成为一根横梁。玩家不输入真实账号和密码，也不连接网络，只需要借这些熟悉的界面物体越过桥面缺口。

这一段的第一笑来自识别，后续乐趣来自平台质量、落点和两人牵引关系。

### 4. 200—300 米：期末任务风暴与破防水，约 40—70 秒

屏幕边缘不断出现“未交报告”“还有一章”“马上答辩”等任务卡，任务卡会挤压可用空间。玩家无法把任务全部清空，只能合作取到一瓶破防水。饮用后，环境和障碍减速，但玩家输入仍然及时响应，两人趁减速阶段通过最后一段。

终点的 `Lucy 河`补给只作为清楚的视觉仪式，不要求观众了解具体糕点争议。

### 5. 结算：把本局动作变成一条解曲线，约 10—15 秒

程序把两位玩家的实际轨迹绘制成一条“本局解曲线”，显示用时、破防次数和互相拉回的次数。结算不使用传统的死亡数或击杀数。

在当前小段内，“破防”轨迹可以凝固为少量可踩线段，作为自动降低难度的补救机制；玩家不需要故意失败才能通过。跨小段或跨多局长期保留所有历史轨迹仍属于后续功能，不能在最小可玩版本中提前承诺。

## 四、控制和物理规则

### 默认双键盘控制

- 玩家一暂用 `A/D`移动、`W`短跳；玩家二暂用左右方向键移动、上方向键短跳。
- 角色不会瞬间达到最大速度，按键施加的是驱动力而不是直接设置位置。
- 游戏不要求任何一位玩家同时按住三个键，并提供 `WASD + 方向键`和 `WASD + IJKL`等备用映射。
- `R`：两位玩家共同确认后从最近检查点重来，避免误触。

### 可选键盘加鼠标模式

键盘加鼠标可以保留为后续实验模式，但不再是课程演示的依赖。若实现，鼠标拖动只产生有上限的力，不会直接传送角色。

### 搭子绳

搭子绳采用简化的弹簧—阻尼模型。弹簧使被拉开的两位玩家互相靠近，阻尼消耗一部分往复振动，避免角色无限抖动。实现时使用固定时间步长、限制最大弹力，并在低帧率时执行少量物理子步，从而降低穿墙和数值爆炸风险。

第一版不模拟绳子的缠绕、打结和连续柔性形变。画面上可以把绳子画成略带弯曲的线，但物理上只计算两端之间的连接。真实绳索模拟的开发和稳定性成本明显高于本课程作业的收益。

## 六、首版范围和牺牲顺序

### P0：必须完成，否则不能称为游戏

- 一台 Windows 电脑上，两个人能共用一把键盘完成一局；
- 两个角色、搭子绳、重力、地面碰撞、检查点和破防重置稳定工作；
- 一局包含三个 100 米段，时长 2—4 分钟；
- 三个主事件能够在没有说明文字的情况下被看懂；
- 游戏不联网，不读取真实校园账号，不依赖外部服务；
- 基础 MATLAB 可以运行核心游戏。

### P1：课程展示应当完成

- MATLAB 曲线变成北湖的开场反转；
- 当前小段内，破防前的短轨迹凝固为可踩的“错误解曲线”；
- 结算页把本局轨迹重新画成解曲线；
- 背景音乐、碰撞、弹绳、鹅叫和破防水音效；
- 控制、主题、关卡和素材路径集中配置；
- 适配 16:9、16:10 和 3:2 横屏窗口；
- 对 Symbolic Math Toolbox 提供真实求解和无工具箱回退两条路径。

### P2：有余力再做

- 角色互换控制；
- 羊驼、孔雀或艾比特第四事件；
- 最近几局的失败轨迹跨关卡、跨启动长期改变道路；
- 有限三圈内的事件组合变化；
- 使用 MATLAB Compiler 打包独立安装程序。

### 明确不做

- 3D 场景、实时光照、视频背景和大规模粒子特效；
- 怪物、武器、生命值和角色死亡；
- 真实账号登录、校园网请求或云端排行榜；
- 真实柔性绳索、流体或完整刚体物理引擎；
- 把所有校园梗做成一闪而过的贴图；
- 为了展示工具箱而在每一帧执行符号计算；
- 首版同时维护 R2025b、R2020b 和独立 EXE 三套同等优先级的发行物。

如果开发或演示时间不足，牺牲顺序是：第二、三圈和额外事件 → 华丽粒子与动画 → 轨迹继承 → Symbolic 开场的实时求解。不能牺牲双人核心操作、Windows 稳定性和第一圈的完整因果关系。

## 七、MATLAB 技术方案

### 1. 运行形态

首选普通 `.m` 文件和标准 `figure` 图形窗口，而不是把主要逻辑封装进难以阅读的 `.mlapp` 文件。程序入口建议为 `startGame.m`，学生只需要在 MATLAB 中打开项目目录并运行该文件。

核心实现使用基础 MATLAB 提供的 `figure`、`axes`、`image`、`patch`、`line`、`text`和键盘回调。图片使用 PNG，音效优先使用 WAV；不使用 `imshow` 等需要 Image Processing Toolbox 的便利函数。

### 2. 代码结构

建议目录如下：

```text
startGame.m                 唯一的学生运行入口
src/                        游戏循环、输入、物理、碰撞、渲染
config/                     画面、音量、按键和性能档位
levels/                     三个 100 米段的关卡数据
assets/images/              梨、动物、校园界面和背景图片
assets/audio/               背景音乐和音效
optional/                   Symbolic Math Toolbox 展示与后续打包代码
tests/                      不启动完整游戏的基础检查
docs/                       需求、来源、运行说明和验收记录
```

初版优先使用函数和结构体保存状态，不建立复杂类继承体系。文件需要分工清楚，但不能拆成几十个只含几行代码的小文件，以免三位初学者无法从入口追到完整流程。

### 3. 游戏循环

- 物理计算使用固定时间步长，目标为每秒 60 次；
- 画面目标为每秒 30 帧，低配模式允许降到每秒 20 帧；
- 图形对象在进入关卡时创建，运行中只修改位置、可见性和图片数据，不在每一帧删除再重建；
- 同一时刻动态物体控制在约 15 个以内，总图形对象控制在约 80 个以内；
- 每次破防只把最后一小段轨迹降采样为少量直线段，当前场景保留数量设上限，避免碰撞计算和画面无限增长；
- 不在游戏循环中读取磁盘、解码音频、执行符号求解或创建新窗口；
- 程序持续记录实际帧耗时，连续低于性能目标时关闭装饰粒子和复杂透明效果。

MathWorks 官方文档说明，`drawnow limitrate`会把图形刷新限制为每秒 20 次。因此，正常 30 帧模式不能简单地在每一帧都调用它；实现时应当让 60 次物理更新和 30 次显式画面更新分开，在低配档位才使用 20 帧限速策略。

### 4. 屏幕适配

游戏内部使用固定的逻辑坐标，不把物理尺寸直接绑定到窗口像素。16:9、16:10 和 3:2 屏幕显示同一块游戏区域，多余空间使用背景留边。这样可以避免改变窗口比例后跳跃距离、碰撞范围和关卡难度发生变化。

Windows 的 125% 或 150% 显示缩放必须纳入实机测试。字体、按钮和鼠标位置使用窗口实际尺寸计算，不能假设演示电脑一定是 1920×1080。

## 八、电脑性能判断

### 已确认的硬件口径

用户已经确认，目标电脑确实是 **Intel Core Ultra 9／Core Ultra 5 Series 2** 一类的新电脑，只有核显。

在上述 Core Ultra Series 2 口径下，结论是：**这款 2D MATLAB 游戏不需要独立显卡，这类电脑具有很大的性能余量。** Intel 官方产品列表显示 Series 2 包含多款 8 核及以上移动处理器并自带 Intel Graphics 或 Arc 核显；代表性的 Ultra 5 228V 支持 AVX2、OpenGL 4.6 和 DirectX 12.2。MATLAB R2025b 的官方建议是四核、支持 AVX2、16 GB 内存，以及支持 WebGL 2.0、约 2 GB 图形内存的 GPU。现代集成显卡使用共享系统内存，但足以处理本方案限制下的少量 2D 图形对象。

当前仍不能声称“已经稳定 30 帧”，因为尚未在目标 Windows 电脑和 MATLAB 中运行原型。正确的结论是“硬件规格明显足够，实际帧率需要用首个技术原型验证”。

### 建议测试档位

| 档位 | 目标电脑 | 预期 |
| --- | --- | --- |
| A：正式演示 | Core Ultra 5/9 Series 2、16 GB 或更多内存、核显、Windows 11、R2025b | 1080p 或同等像素量下 30 帧目标 |
| B：保守档 | 8 GB 内存、受支持的四核 x86-64、核显、R2025b | 关闭装饰特效，以 20 帧稳定运行 |
| C：旧版兼容 | 能运行 R2020b 的 Windows 电脑、8 GB 内存 | 只做核心玩法冒烟测试，不作为首发阻塞项 |

若电脑只有 8 GB 内存，核显还会占用部分共享内存。演示前应关闭大型浏览器页面和其他占用内存的软件。项目不使用 Parallel Computing Toolbox 的 GPU 计算，因此独显、CUDA 和显存计算能力都不是依赖。

## 九、安装什么 MATLAB

### 推荐安装

正式开发和答辩电脑安装：

1. **MATLAB R2025b 的最新可用更新**：必装，是运行游戏、绘图、播放音频和执行基础数值计算的主体。MathWorks 说明新下载安装会包含该发行版当时的最新累计更新；已有安装可以在 MATLAB 中检查更新。
2. **Symbolic Math Toolbox**：建议安装，用于开场的常微分方程展示；核心游戏必须提供没有该工具箱时的回退路径。

先不要安装 Simulink、Image Processing Toolbox、Audio Toolbox、Computer Vision Toolbox、Parallel Computing Toolbox、MATLAB Coder 或各种硬件支持包。它们不是当前方案的依赖。MathWorks 官方给出的 R2025b Windows 空间为：仅 MATLAB 约 4.2 GB，典型安装约 4—6 GB，全部产品约 24 GB。由于下载安装缓存、Symbolic Math Toolbox、项目素材和更新也需要空间，建议安装前至少保留 15 GB 可用空间，20 GB 更从容；不要为了“以后可能用到”直接全选产品。

Windows 在线安装的基本路径是：从 MathWorks 下载对应版本的 Windows 安装器，运行安装程序，登录具有许可证的 MathWorks 账号，选择许可证和产品，完成安装。北京理工大学 2019—2020 年公开采购记录能够证明学校当时提供过全校 MATLAB 授权，但没有找到足以证明 2026 年当前授权状态和具体入口的公开材料。因此，三位学生需要用自己的学校身份登录学校软件平台或 MathWorks 账号，实际确认当前许可证；本文不能把旧采购公告当成今天仍然有效的安装凭据。

R2025b 官方支持的普通桌面 Windows 版本是 Windows 11 23H2 或更高版本，以及 Windows 10 22H2。正式演示电脑若不是这些版本之一，需要单独核对，不能仅凭“MATLAB 能打开”判断为受支持环境。

### R2020b 怎么处理

R2020b 只作为兼容性测试版本，不作为主要开发版本。它的官方 Windows 要求较低：4 GB 内存最低、8 GB 推荐，仅 MATLAB 约 3.5 GB、典型安装约 5—8 GB，而且不要求特定显卡；OpenGL 3.3 和 1 GB 图形内存只是推荐配置。

但 R2020b 的官方系统列表只列出当时的 Windows 10、Windows 7 和 Windows Server，并未列出后来发布的 Windows 11。因此，“R2020b 在某台 Windows 11 电脑上能启动”不能等同于 MathWorks 官方支持。新电脑优先使用 R2025b，R2020b 只在确有课程或实验室环境需要时测试。

为了降低兼容成本，代码将尽量遵守 R2020b 可用的语法和 API：使用普通 `.m` 文件、传统名称—值参数写法，避免依赖近年新增的界面组件。这个目标是“尽量兼容”，不是在未测试前承诺完全兼容。

### 双击启动与是否打包成 EXE

用户已经确认答辩电脑能够安装 MATLAB，但希望尽量做到双击直接运行。因此首版计划同时提供 `startGame.m`和一个 Windows 启动文件。双击普通 `.m`文件通常会启动 MATLAB 并在编辑器中打开文件，不会自动运行；启动文件则使用 MATLAB 的 `-sd`参数切换到项目目录，并用适合交互程序的 `-r`参数执行 `startGame`。这仍然是“由已安装的 MATLAB 运行”，不是独立 EXE，也不需要 MATLAB Compiler。

若最终必须在没有 MATLAB 的电脑上运行，才需要开发电脑另有 MATLAB Compiler 许可证来生成独立程序，目标电脑再安装与编译版本匹配的免费 MATLAB Runtime。Runtime 不是开发环境，也不能让学生查看和修改源代码；它还会增加安装体积和首次启动成本。因此，真正的独立打包仍属于 P2 发布工作。

## 十、风险顺序和验证方法

| 风险 | 当前判断 | 最先验证什么 |
| --- | --- | --- |
| 双人同时按键、键盘鬼键和窗口焦点 | 中高 | 做五秒按键检测和只有两个圆、一条绳的 30 秒 Windows 原型 |
| 弹性连接导致抖动、穿墙或数值爆炸 | 中高 | 固定步长、弹力上限、简单矩形地面和连续 10 分钟运行 |
| MATLAB 图形刷新不稳定 | 中 | 记录帧耗时，比较 30 帧和 20 帧档位，禁止每帧重建对象 |
| 校园梗看得懂但不好玩 | 中 | 先用灰盒测试完整事件，再替换正式图片和音效 |
| 错误解曲线碰撞过于复杂或被玩家误解为必须失败 | 中 | 只保留短线段并作为补救路线；正常路线始终可以一次通过 |
| `🍐` Emoji 在 Windows/MATLAB 显示异常 | 高概率 | 不依赖系统 Emoji，项目自带梨形图形资源 |
| R2025b 与 R2020b 行为差异 | 中 | 核心玩法稳定后在 R2020b 做一次冒烟测试 |
| Symbolic 工具箱未安装 | 中 | 启动时检测工具箱，自动使用预计算结果 |
| 独立 EXE 打包和 Runtime 安装复杂 | 中高 | P2 才验证；课程演示优先从 MATLAB 直接运行 |

开发顺序必须按风险，而不是按画面好看程度：

1. 先做无美术的双人输入、两体物理和关窗清理原型；
2. 再做一个约 60—90 秒、只有鹅学长事件的竖切版本；“竖切”指从开场、操作、事件到结算全部走通的短版本；
3. 在目标 Windows 电脑测帧率、输入和窗口缩放；
4. 技术稳定后扩成三个 100 米事件；
5. 最后替换正式视觉、音频并接入可选 Symbolic 展示；
6. 只有课程明确要求独立运行时，才评估 MATLAB Compiler 和 Runtime。

## 十一、首版验收条件

满足以下条件后，才可以把 v0.1 称为“可交付课程版本”：

- 在一台目标 Windows 11、R2025b、只有核显的电脑上连续完成三局，没有崩溃、输入失效和残留窗口；
- 从运行 `startGame.m`到出现可操作画面不超过 5 秒，不把 MATLAB 自身冷启动时间计入游戏加载；
- 正常档在目标电脑上大部分时间达到约 30 帧，低配档稳定达到约 20 帧；
- 两位玩家同时移动和跳跃时，主要按键组合都能被目标键盘识别；
- 窗口关闭后，程序停止循环并清理音频和回调，不在命令窗口持续报错；
- 在 16:9 和一种 3:2 横屏比例下，角色、文字和按钮不被裁切；
- 关闭网络后仍能完整运行；项目路径包含中文或空格时仍能找到素材；
- 未安装 Symbolic Math Toolbox 时，核心游戏仍可完成；
- 三位参与者都能在不阅读源码的情况下，在 15 秒内明白自己的操作；
- 至少两位当前北理工学生能立即认出北湖鹅、校园网登录和破防水三个场景。最后一项是小规模用户确认，不是对全校认知度的统计证明。

R2020b 验收单独记录。若 R2020b 失败但 R2025b 全部通过，首版仍可发布，但必须在 README 中明确版本限制。

## 十二、2026-09-03 用户反馈后的状态

已经确认：

- 目标电脑属于 Core Ultra 5／9 Series 2 等新设备，性能不是主要风险；
- 答辩电脑能够保证安装 MATLAB；
- 希望两位玩家默认共用键盘，不把外接鼠标作为必要设备；
- 希望在 MATLAB 已安装的前提下，仍然提供双击启动方式。

当前最重要的未决问题不再是安装和硬件，而是弹性连接本身是否足够好玩，以及“数据变世界、运动再变数据”的闭环是否能在游玩过程中被玩家感知。详细审查见[设计理由与第一次自我审查](design-rationale-v0.1.md)。
