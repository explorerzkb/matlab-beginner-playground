# 当前项目状态与接续入口

更新日期：2026-09-03

## 当前结论

项目已经从研究和概念发散阶段切换到实现阶段。首版产品、四个正式关卡、双人关系、视觉基线和技术边界已经写入 [`game-spec-v1.md`](game-spec-v1.md)，不再把它们视为候选方案。

当前仓库仍没有 `.m` 游戏代码，也没有 `assets/game/` 运行时素材。现有成果是实现规格、开发计划和经过收缩的关卡参考资料，因此还不能声称游戏已经可运行、好玩或在 Windows 上通过性能验证。

## 已冻结范围

- 二维横向平台游戏，两名玩家共用一把键盘；
- 两只同体型、同能力的小梨角色，由一根松弛时不施力、拉直后传递拉力的普通绳连接；
- 两只梨不画永久可见的腿，不加叶子或叶柄；用梨身倾斜、挤压、弹跳、阴影和表情变化表现运动，避免额外的人形步态系统；
- 自由左右移动和跳跃，不采用强制自动前进；
- 序章之后依次完成四关：北湖动物、北理桥校园网、艾比特导航故障、期末任务风暴与破防水；
- `Lucy 河`是最后一关的终点仪式，结算把本局真实轨迹重新画成 MATLAB 曲线；
- 没有怪物、战斗、生命值和角色死亡；失败后整对玩家回到本关检查点；
- 视觉采用“校园漫画平涂 + MATLAB 图形语言”，不再继续比较旧画风预览；
- 核心运行环境为基础 MATLAB R2025b，Windows 11 是最终验收平台；
- 游戏离线运行，不连接 `10.0.0.55`，不采集账号密码，不依赖云端服务。
- 第二关直接显示经过隐私检查的真实校园网登录页截图，不由生成模型或 MATLAB 图元重画；MATLAB 只把它作为图片移动和显示，碰撞数据独立存在。
- 所有画面、场景和建模任务执行 `visual-spatial-sop.md`，必须实际打开参考图并验证桥端、支撑、岸线和前后景关系。

完整行为和每关职责见 [`game-spec-v1.md`](game-spec-v1.md)。

## 实际机器与验证边界

- 当前开发机是 Apple Silicon Mac，已发现 MATLAB R2025b 应用，但当前尚未记录本项目的实际启动结果。
- 目标机是 Core Ultra 5／9 Series 2、核显、Windows 11、MATLAB R2025b 的笔记本；硬件预算充足只是规格判断，不等于实测通过。
- 答辩电脑能够安装 MATLAB。它是否与目标测试机为同一台、准确型号、屏幕比例和键盘型号仍待登记。
- R2020b 只做有余力时的兼容性冒烟测试，不阻塞首版。
- GitHub 是代码托管远程，不是游戏运行环境；项目没有服务器、数据库或外部 API。

## 尚待运行回答的问题

以下不是继续写方案才能回答的问题，应通过原型和实机测试解决：

1. 普通绳的长度、最大拉力和阻尼取值怎样才能既可控又能产生合作笑点；
2. 目标键盘能否同时识别两位玩家最常用的移动加跳跃组合；
3. MATLAB 图形窗口能否稳定完成 60 Hz 物理更新和约 30 FPS 画面更新；
4. 首次接触者能否在 15 秒内理解自己的角色、绳和近期目标；
5. 四关总时长是否落在约 4—6 分钟，课堂展示是否需要提供短演示模式。

这些项目只能记录为“待验证”，不能在运行前写成已经通过。
