# 连续校园世界游戏规格 v2

状态：北湖第四轮与校园网第五轮本机实现完成，等待真实学号和目标 Windows 真人验收
更新日期：2026-09-04

文件名为兼容项目入口继续保留 `game-spec-v1.md`，本文内容已经覆盖旧的四个硬关卡规格。开发不得从历史区恢复已经撤销的关卡卡片、逐关重建状态或旧版校园网卡片玩法。

## 1. 产品目标

这是一款两名学生共用一把键盘游玩的 MATLAB 二维合作平台游戏。两只能力完全相同的小梨由普通绳连接，从 MATLAB 坐标轴落入良乡校园，在一张连续地图中经过北湖、校园网界面、南北交通和乐学任务风暴，最终到达 Lucy 河。

一次完整流程目标约 4—6 分钟。玩家应感到自己经历了一趟连续校园旅程，而不是依次打开四个彼此割裂的小游戏。代码内部可以划分区域用于组织、测试和性能，但玩家不能看到关卡标题卡、黑屏加载或逐关状态重建。

MATLAB 学习价值来自真实的数据流：输入改变速度，速度和外力改变位置，碰撞与绳力共同约束运动，区域状态改变机关，检查点保存进度，最终轨迹数组重新由 `plot` 绘制。

## 2. 角色、输入与普通绳

两名玩家是同物种、同体型、同质量、同碰撞体和同能力的原创梨形小生物。

- 玩家一：`A`、`D`移动，`W`跳跃；
- 玩家二：方向键移动与跳跃；备用为 `J`、`L`、`I`；
- `Esc`暂停，长按 `R`共同回到最近检查点，`Q`退出；
- `Space`长按约 0.35 秒，饮用共享背包中的破防水；
- 开始前保留五秒双人按键检测，所有提示从配置读取。

绳只连接两只梨身体侧下方的连接环。距离短于绳长时保持松弛且不产生推力；超过绳长时使用有上限的弹簧—阻尼近似产生拉力。绳不缠绕地形、不打结、不断裂，也不能主动伸缩。

## 3. 连续地图

玩家可见流程固定为：

```text
MATLAB 坐标轴
→ 北湖动物区域
→ 巨型校园网认证页面
→ 艾比特路线提示
→ 喷泉与南北交通岔路
   ├─ 上层北理桥
   └─ 下层红绿灯
→ 乐学选课倒计时
→ 课程与通知任务风暴
→ Lucy 河
```

- 数据点落下后直接进入北湖，不播放序章结束卡；
- 校园网页面在世界中展开成可攀爬空间，登录成功后按钮成为下一段出口；
- 喷泉把玩家送往上层北理桥，不进入喷泉则自然来到地面红绿灯；
- 两条交通路线在南区重新汇合，均可正常通关；
- 乐学界面在道路末端展开，完成任务风暴后抵达 Lucy 河；
- 只有 Lucy 河之后进入轨迹结算。

摄像机通常连续跟随两名玩家；进入校园网和乐学页面时可以平滑锁定到页面范围，离开后恢复跟随。镜头变化不能重新创建角色或清空全局状态。

## 4. 北湖动物区域

北湖红桥、湖岸和树列继续作为现实识别背景。鹅鸭是不会造成死亡的移动软障碍：接触时只产生有限水平推力，不进入通用刚性碰撞体，不得把角色夹在动物、坑边或桥下。玩家可以等待、跳过，也可以顶着推力穿过；画面必须用朝向、脚步和轮廓让其移动方向可读。

北湖动物段不能只是两个动物之间的短走廊。第三轮把该段扩展到至少两个完整镜头宽度，鹅与鸭采用不同体型、速度和活动范围，形成可以观察、等待、跳过和借绳配合的连续动物路线；不以堆高伤害延长时间。

羊驼是可选但必须有实际收益的捷径：玩家接近鼻部会触发有预告和冷却的喷嚏助推，给角色施加有上限的斜向冲量；喷嚏必须能够把一只梨送上明确标出的高层红桥捷径，绕过后半段动物与地面缺口，并通过绳带动另一只。桥底到地面的净空至少容纳两倍角色高度，羊驼与桥头之间不得留下小于角色宽度且可能封顶的夹缝；忽略羊驼时仍有较慢但完整可行的地面路线。测试必须证明喷嚏能抵达抬高后的捷径落点、桥下可通行且鹅鸭不会形成刚性死锁，而不只证明速度数值发生变化。

## 5. 校园网物理页面

经过隐私检查的真实校园网截图作为完整页面主体，但页面不再是一张上下浮动的卡片。

页面原截图的像素坐标是唯一布局依据。整张截图只能使用同一个等比例变换映射到世界坐标；公告框、用户名、密码、记住密码、登录、自助服务和两类充值控件的视觉与交互矩形必须由各自在原图中的位置换算，不得为了平台顺序、镜头宽度或通关方便重新排列。允许在原控件位置叠加状态色、文字和碰撞反馈，但不能改变控件中心、相对间距或页面分栏。

- 北湖高层红桥连接到页面左侧；左侧“通知公告”整块面板是实体落脚物，两只梨必须从红桥跳上公告框顶部，再向右进入登录区；
- 任意一只梨的身体经过用户名输入区，就一次性自动显示本组三位同学的学号，密码区同时显示恰好十个星号。学号只从集中配置读取，不创建真实文本输入框，也不收集运行时输入；
- “记住密码”保留为可选的有语义检查点；它是触发区，不阻挡从用户名区域落向按钮的路线；
- “登录”和“自助服务”是原位、固定的两块实体平台。此前加在页面下方的两块浅蓝辅助平台删除；在线充值和经费卡充值只保留在原页面画面中，不再承担碰撞或弹跳；
- 两只梨同时站在“登录”平台上时立即完成认证并开门；单人站上去只显示“还差一只梨”，不需要额外长按；
- 每局有小概率在自动填表后随机出现一次“校园网卡了”彩蛋：先显示文字提示，随后“登录”和“自助服务”两块平台短暂消失，可能让站在上面的梨掉落。平台随后自动恢复，事件不会重复，复活后仍有安全重试路线；
- 登录成功后，玩家可经自助服务平台跳到交通区域入口。

程序不创建文本输入框、不获取账号密码、不打开浏览器、不访问校园网，也不把截图伪装成真实认证窗口。

## 6. 南北交通二选一

艾比特只给出路线提示，玩家通过实际移动选择路线。两条路线起初同时开放；两人共同进入同一路线的首个稳定区后才确认选择，在此之前可以返回。分开选择时不会推进，普通绳会自然限制距离。

上层北理桥路线由喷泉进入。水柱是周期性向上冲量区，可以先喷起一只梨，再借绳带动另一只；桥面缺口要求轮流站稳和拉回同伴。这条路线稳定，但合作要求较高。

下层红绿灯路线包含车辆绿灯、黄灯、全红和行人绿灯。它必须按“安全等待区 → 停止线 → 斑马线 → 对岸安全区”的顺序建模：

- 车行阶段，车辆只在道路危险区循环，等待区不能被车辆扫过；
- 行人绿灯前先经过全红清空阶段，所有车辆必须完全离开斑马线和两侧步行入口；
- 行人绿灯期间停止车辆不参与伤害判定，入口开放时间必须足够两只受绳约束的梨从等待区抵达对岸；
- 行人红灯时用可见的软护栏阻止误入，不能靠一辆停在玩家身上的车充当门；
- 车辆碰撞只在车辆实际行驶且与斑马线危险区重叠时触发共同复活。

交通完成标准不是“红绿灯互斥”或“车会动”，而是自动测试和真人试玩都能从路口前完整抵达对岸，且按规则等待不会受伤。赶上行人绿灯时路线更快，错过则要在安全区等待。

当前材料只支持“北区—道路或桥—南区”的结构过渡，游戏不得声称精确复刻现实桥面、红绿灯位置或完整交通组织。

## 7. 乐学选课与任务风暴

乐学区域使用用户提供的两张 2852×1654 截图作为布局坐标系，但不直接提交含姓名、学院、访问日期等个人信息的原图。每个页面使用单一等比例映射，页面边界、顶部栏、主体蓝色区域、时间线、倒计时、右侧用户卡、开始选课按钮、教程列表、侧栏和“我的课程”卡片都保持原截图的相对位置与尺寸；不得为了横版流程把原本左右并列的元素改成线性排列。

必须把允许保留的公共结构与需要脱敏的内容分开：个人姓名、头像、学院、日期和真实课程文字使用同位置同尺寸的匿名占位内容覆盖，页面栅格和控件位置不变。玩法碰撞区叠加在对应原控件上；额外的任务卡只能从通知入口生成，不能挤动原页面布局。

第一阶段是选课倒计时页面。倒计时数字是可站立平台，翻页前必须预告，翻页只产生受限的小幅抛起。两人共同压下“开始选课”按钮后进入乐学首页。

第二阶段中，“我的课程”卡片、教程条目和通知栏组成路线；消息红点“50”代表高压通知，只分批释放少量任务卡，不生成五十个实体。任务卡造成破防和击退，逐渐压缩安全空间。玩家可以饮用破防水减轻压力并获得短时强化，最终共同抵达 Lucy 河。

## 8. 破防值与热带风味冰红茶

`破防值`是 0—6 的当前压力状态，不是累计失败次数：

- 任务卡等轻度碰撞使破防值增加 1，并击退角色；
- 坠落、撞车等严重失败使破防值增加 2，并让两人回到最近检查点；
- 达到 6 时触发“彻底破防”，短暂停顿后共同复活，破防值恢复到 3；
- 累计失败次数单独记录，任何道具都不能倒扣已经发生的失败历史。

“破防水”正式设定为热带风味冰红茶：

- 用户指定的 `assets/game/images/items/tropical-iced-tea.jpg` 是唯一原始视觉依据；所有场内拾取物必须使用由它确定性抠出的透明图 `tropical-iced-tea-cutout.png`，不得再用带白底的 JPEG、彩色矩形、其他商品图片、其他包装或自由生成造型代替；
- 因拾取物在最终画面中只有几十像素，允许从这张图做紧裁、低分辨率取样、像素化或忠于同一瓶身与包装识别特征的简化重绘；这不授权引入第二套设计；
- 四处拾取物在上一版基础上整体再放大 25%，碰撞范围统一为 1.5×1.8125 世界单位，保持原中心位置与落地高度；画面继续额外横向放宽 25%，瓶盖局部宽 14%、高 8%，并使用约 1 个低分辨率纹理像素、34% 不透明度的深紫描边，以提高辨识度并柔化粗糙透明边缘；
- 地图多处可拾取，使用共享背包，最多携带两瓶；
- 长按 `Space`饮用一瓶，使破防值减少 2，最低为 0；
- 同时获得约六秒强化：跑动加速度和跳跃小幅提高，环境击退减弱；
- 绳长、绳力上限、碰撞体和固定时间步不变；
- 即使破防值为 0，也允许为了强化主动饮用；
- 已拾取的瓶子在复活后保持消失，不能通过反复失败刷取；
- Lucy 河把当前破防值清零。

## 9. 检查点与复活

本项目只做单局检查点，不做跨次启动的磁盘存档。固定恢复点包括：初始坐标轴、北湖出口、校园网“记住密码”、交通路线安全点、南区补给处和乐学“我的课程”。

检查点保存两人恢复位置、已完成大型事件、交通路线、已拾取与已饮用道具以及当前破防值。临时车辆、交通灯、喷泉脉冲和任务卡恢复为预设安全相位。复活后两人并排出现、速度清零、绳保持松弛，目标一秒内恢复控制。

失败使用“被劝返”“彻底破防”和共同复活表达，不加入写实死亡、尸体、生命条、永久惩罚或跨局养成。

## 10. 视觉、声音与证据边界

第二轮灰盒已经结束，最终视觉阶段已在开发机实现。北湖、体育馆／装备展示、文博馆和校徽作为独立识别锚点进入连续世界；背景负责质感和环境层，碰撞、平台、桥端、网页控件与通行空间仍由代码定义并继续执行 `visual-spatial-sop.md`。

用户提供的玩法图只用于校准手绘质感、层次、色彩密度和完成度，不得用其中的桥、岛、悬台、建筑或抽象空间关系补齐校园事实。不同现实地标在连续世界中的相邻排列属于游戏章节编排，不表示它们现实中相邻。

两只梨不画永久可见的腿，不加叶子或叶柄；用形变、倾斜、阴影和表情表达运动。撞墙／撞顶时使用痛苦表情，向上腾空时使用自由开心表情，绳绷紧时瞳孔朝受力方向偏移。视觉形变不得改变碰撞盒。

北湖动物不能停留在椭圆、直线脖子和圆点头的示意符号。羊驼使用可辨认的侧身轮廓、蓬松身体、直立颈部、口鼻、耳朵、尾巴与蹄部；鹅鸭至少具有身体轮廓、翅膀、眼睛、喙、腿脚和面向移动方向的姿态。视觉细化不得扩大其碰撞或推力范围。

真实校园网截图是运行时例外；用户提供的乐学与选课截图只作参考，原图含个人信息，不得进入 Git 或运行时资产。乐学结构使用脱敏的程序图形重新表达，不连接真实页面。

冰红茶图片是用户明确指定的另一项运行时图片资产。各拾取点共享同一透明 PNG，图片缩放保持宽高比且四周不得出现白色矩形底；抠图和像素化不得改变独立碰撞矩形。素材或透明通道缺失时应让检查失败，不得静默回退到 JPEG 白底或程序图元瓶子。

HUD、暂停层和按键提示以高对比、键盘可扫读和不遮挡核心动作区为准；UI 检查不得反过来主导场景构图或角色设计。校园网与乐学页面继续使用冻结的统一像素映射，视觉优化不得改动其内部布局和控件位置。

声音只提供动作确认；缺少音频时必须完整可玩。

## 11. 技术与完成标准

- 主版本 MATLAB R2025b，核心只依赖基础 MATLAB；
- 物理目标 60 Hz，渲染目标约 30 FPS，低配档约 20 FPS；
- Windows 11 目标电脑实测是最终完成条件，Mac 只算开发证据；
- 一张连续地图能从坐标轴完成到 Lucy 河，区域之间不重建玩家状态；
- 两条交通路线都是真实可行选择；
- 红绿灯路线存在可复现的双人端到端通行测试，安全等待不会触发车辆碰撞；
- 校园网认证不能由单人或未自动填表时提前触发，也不会获取文本焦点；
- 校园网公告框、登录、自助服务和交通入口形成连续可达路线；随机掉线后平台会恢复且检查点复活不会形成死局；
- 交通灯不会让行人绿灯与穿越车辆同时生效；
- 破防值、冰红茶、检查点和已拾取道具在全地图保持一致；
- 冰红茶的全部场内实例只来自用户指定图片或其受限派生版本，不存在另一套占位瓶子；
- 四到六分钟流程连续完成三次，没有崩溃、数值爆炸或关窗残留循环；
- 关闭网络、中文或空格路径、没有 Symbolic Math Toolbox 时仍可运行；
- 运行时与仓库不包含用户提供乐学截图中的个人信息；
- 校园网与两张乐学页面的互动控件通过同一页面变换从原图像素坐标映射，位置回归测试不允许单独挪动控件；
- 试玩者能说清普通绳、校园网控件、喷泉、路线选择、冰红茶和任务风暴的作用。

“好玩”“一眼就懂”、目标时长和 Windows 表现必须由真实试玩记录证明，不能仅凭代码存在宣称通过。
