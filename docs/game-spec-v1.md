# 首版游戏规格 v1

状态：已冻结，可进入实现
更新日期：2026-09-03

本文是首版游戏的唯一产品和玩法规格。除非用户明确改变需求，开发不得从历史文档恢复其他关卡、角色关系、三圈结构、无限模式或画风。

## 1. 产品目标

这是一款供两名学生围在同一台电脑前立即游玩的 MATLAB 二维平台游戏。它应当在约 4—6 分钟内完成一次有开场、升级、高潮和结算的合作体验，让旁观者能看懂“一个人的动作会通过绳影响另一个人”。

MATLAB 学习价值来自实际程序结构和数据流：输入改变速度，速度改变位置，碰撞和绳力共同约束运动，关卡读取玩家状态，最终轨迹数组重新被 `plot` 绘制。它不是调参数看曲线的演示。

## 2. 核心循环

玩家观察前方障碍，分别控制两只小梨跑动和跳跃；当两人距离达到绳长上限时，绳张力把双方互相拉回。玩家需要轮流站稳、借力、接住或拖回同伴，到达本关出口。

失败不表现为死亡。任一角色跌出安全区域、两人卡死或玩家主动重来时，两名角色共同回到最近检查点，关卡状态恢复，破防次数加一。重试目标应在一秒左右恢复操作。

## 3. 角色与输入

两名玩家角色是同一物种、同一体型、同一质量、同一碰撞体和同一能力的原创梨形小生物。

- 玩家一：暖梨黄／琥珀色，胸前实心圆；默认 `A`、`D`移动，`W`跳跃。
- 玩家二：湖水青色，胸前实心菱形；默认左右方向键移动，上方向键跳跃。
- 备用映射：玩家二可切换为 `J`、`L`移动，`I`跳跃。
- `Esc`暂停；`R`需要短暂按住或双人确认后重置本关，避免误触。

开始界面必须提供五秒双人按键检测，分别显示两组移动和跳跃输入是否被同时识别。键位和提示统一从配置读取。

移动采用自由左右跑跳，不强制自动前进。按键产生水平驱动力，角色有加速、最大速度、地面摩擦和空中控制；跳跃只有接地时触发，不加入二段跳。首版不实现抓边、攀爬、冲刺或不同角色技能。

## 4. 普通绳规则

- 绳只连接两只角色腰部的连接环；
- 距离小于绳长时松弛，不产生推力；
- 距离接近或超过绳长时产生拉力和阻尼，限制继续分离；
- 绳不缠绕地形、不打结、不断裂，也不能被主动伸缩；
- 画面可用轻微下垂曲线表达松绳，但物理只计算两个端点；
- 数值实现可以使用有上限的弹簧—阻尼近似，但玩家看到和理解的规则始终是“普通绳拉直后才受力”。

绳的参数属于灰盒调试参数，不属于固定策划数字。只有试玩后才能冻结具体绳长、最大拉力和阻尼。

## 5. 视觉和声音基线

首版采用“校园漫画平涂 + MATLAB 图形语言”：清楚的深色轮廓、少量纯色块、可读的平台边缘，以及坐标轴、网格、数据点和曲线等 MATLAB 视觉元素。旧的五种画风预览不再参与选择。

两只角色保持真实梨的上窄下圆轮廓、柔和体积和少量果皮斑点／颗粒质感，使用点眼、简单嘴线和可变化的表情。角色不画永久可见的腿，不加叶子或叶柄，也不套用人形跑步循环；移动通过整体轻微倾斜、挤压与拉伸、短距离弹跳、落地回弹和地面阴影表达。视觉形变不得改变碰撞盒。

两只梨的体型、能力和轮廓完全相同，只用颜色与胸前圆／菱形标记区分玩家，不能只依赖颜色。绳连接身体侧下方可见的小连接环，不依赖腰带、手脚或抓绳动画。

真实校园照片默认只用于内部参考。校园网登录页是例外：第二关直接使用仓库中已经保存的真实页面截图作为有意闯入卡通世界的异质界面，不让生成模型重画，也不使用 MATLAB 图元逐字仿制。截图可以等比例缩放、必要裁边和压缩，但必须保留北理校名、页面布局、红色保密提示和主要配色；进入运行时目录前及正式发布前都必须再次目视检查没有账号、密码和个人信息。

MATLAB 负责把这张 PNG 载入、显示、移动和旋转，碰撞由独立的简单几何数据承担。它不是可操作的认证窗口，不获取焦点、不收集输入、不访问真实校园网。

所有目标效果图、场景背景和正式素材必须执行 [`visual-spatial-sop.md`](visual-spatial-sop.md)。现实地标需要先实际打开索引点名的地图、拓扑和照片；桥、栈道、平台和建筑必须有可解释的岸端、地基、桥墩或其他支撑，真实背景与虚构可玩层必须清楚分离。

声音只承担动作确认和节奏：跳跃、落地、绳拉紧、检查点、鹅叫、界面落下、破防水和结算。缺少音频时游戏仍须完整可玩。

## 6. 固定流程与正式关卡

### 序章：数据点落出坐标轴

目标时长约 15—20 秒。程序先显示一张正常的 MATLAB 曲线，两枚不同形状的数据点发生轻微异常，随后落出坐标轴并长成两只小梨。画面立即出现各自键位，玩家用一次移动和跳跃完成身份确认。

序章只建立角色、输入和“数据进入世界”的因果，不展示长篇文字，也不真的操作 MATLAB 编辑器或系统窗口。

### 第一关：北湖动物借道

目标时长约 45—75 秒。北湖红桥、湖岸和树列构成可识别背景，一队鹅以稳定节奏横穿道路。鹅是移动边界，不攻击玩家，也不能被消灭。

本关只教授跑、跳、绳拉紧和一人站稳后拖回同伴。平台宽、坠落区短、检查点靠近。完成条件是两名角色共同到达出口；单人先到不能结束。

### 第二关：北理桥校园网掉线

目标时长约 60—75 秒。场景明确经过北理桥完成北区到南区的章节过渡。真实校园网登录页截图作为一整张卡片从画面上方落下；截图本身保持可辨认，卡片外框和红色保密提示对应的独立碰撞矩形成为平台或安全落点。

程序不打开浏览器、不访问校园网、不获取文本输入焦点，也不要求账号密码。玩家通过卡片的下落、倾斜和碰撞完成越桥；这一关教授移动平台上的绳力配合。

### 第三关：艾比特导航故障

目标时长约 60—75 秒。`i北理/艾比特`以游戏内校园助手的形式给出路线，但导航箭头、进度条和按钮逐渐成为真实的平台、传送带或门。

核心规则是“界面状态改变道路状态”：启用的路线可站立，禁用的路线变灰并失去碰撞；切换前必须有明显预告。两名玩家需要分别站在两个确认区，使正确路线保持足够长的时间再共同通过。它是连续操作关卡，不要求停下来解文字谜题，也不调用真实校园服务。

本关第一次把前一小段实际轨迹冻结成一条短的可踩 MATLAB 曲线，作为失误后的辅助路线；正常路线始终允许一次通过。

### 第四关：期末任务风暴与破防水

目标时长约 75—100 秒。“未交报告”“还有一章”“马上答辩”等任务卡从屏幕边缘进入，逐渐压缩安全空间。任务卡是环境障碍，不是敌人，玩家不需要把它们清空。

两名玩家合作取得一瓶破防水后，环境物体进入短时间慢动作，但玩家输入保持灵敏。慢动作期间通过最后的密集段，到达 `Lucy 河`补给点即完成关卡。破防水只能在脚本规定的位置触发，不建立背包、商店或复杂道具系统。

### 结算：实际轨迹成为答案

目标时长约 10—20 秒。程序把本局记录的两位玩家轨迹绘制成 MATLAB 风格曲线，显示总用时、破防次数、互相拉回次数和最大绳张力。结算给出重新开始和退出，不进入无限模式。

## 7. 关卡升级关系

四关分别只增加一个主要认知负担：

1. 现实校园中的移动边界；
2. 数字界面具有质量和碰撞；
3. 界面状态直接改变道路；
4. 多源压力下利用已经学会的合作动作完成冲刺。

北湖提供现实起点，校园网和艾比特引入数字校园，任务风暴把压力推到高潮，轨迹结算把游戏重新变回数据。这条升级关系比单个校园梗更重要。

## 8. 失败、检查点与难度

- 每关至少一个起点检查点；较长关卡可增加一个中段检查点；
- 检查点保存角色位置、关卡机关状态和必要计数，不保存瞬时速度；
- 重置后两人并排出现，绳处于松弛状态；
- 同一位置连续失败时，可以出现更宽的平台或短轨迹辅助，但不得要求玩家故意失败；
- 不使用血条、倒计时死亡、永久惩罚或跨局资源养成。

## 9. 技术与发布边界

- 主版本：MATLAB R2025b；核心只依赖基础 MATLAB；
- 主要窗口：传统 `figure` 和 `axes`，不把主体封装进 `.mlapp`；
- 物理目标 60 Hz，渲染目标约 30 FPS，低配档可降到约 20 FPS；
- Windows 11 目标电脑实测是完成条件，macOS 运行只算开发证据；
- 首版提供 `startGame.m` 和 Windows 双击启动文件，不要求独立 EXE；
- R2020b、MATLAB Compiler、跨局存档、第三名玩家和网络排行榜均不属于首版；
- Symbolic Math Toolbox 只能提供可选序章效果，缺少工具箱时必须使用预计算结果或直接跳过，不影响游戏。

## 10. 完成标准

首版只有同时满足以下条件才能称为课程可交付版本：

- 两位首次接触者能在 15 秒内认出自己的角色并开始操作；
- 四关从序章到结算可以连续完成三次，没有崩溃、输入失效和关窗后残留循环；
- 主要双人按键组合在目标键盘上可识别，并有可用的备用映射；
- 正常档大部分时间接近 30 FPS，低配档稳定接近 20 FPS；
- 16:9 和至少一种 3:2 或 16:10 窗口比例下，关键信息不被裁切；
- 关闭网络、项目路径包含中文或空格、未安装 Symbolic Math Toolbox 时仍能完整运行；
- 登录页不会被误认为真实认证窗口，不包含个人账号信息；
- 现实校园画面通过空间合理性检查，没有无支撑桥梁、错误岸线或真假可玩层混淆；
- 两只梨在无腿、无叶的情况下仍能通过形变、阴影和表情清楚表达移动、跳跃、落地和受绳力状态；
- 学生能找到启动入口、按键配置、关卡数据和可替换素材位置；
- 试玩者能描述绳如何影响双方，并能认出北湖动物、校园网、艾比特和破防水四个事件。

“好玩”“一眼就懂”和具体帧率必须由试玩与实机记录证明，不能仅凭本规格宣称已经实现。
