# v21 CPU 与输入轮询复核

本轮针对帧间空闲继续优化。旧代码用 `Thread.yield` 让出线程调度，但循环仍可能持续忙等；现在改成 0.25 ms 的 JVM `LockSupport.parkNanos`。它不调用 MATLAB `pause`，因此不会像 `pause` 那样隐式执行完整 `drawnow`，同时轮询间隔仍远短于 60 Hz 物理步。

在同一台开发 Mac、同一默认档五场景定速测试、相同启动后取样位置，各读取 8 次 MATLAB 进程 CPU。改前为 292.6 / 313.6 / 144.5 / 158.7 / 136.6 / 173.7 / 267.5 / 169.8%，平均 207.1%；改后为 254.0 / 280.5 / 91.7 / 101.1 / 83.9 / 138.8 / 195.6 / 97.1%，平均 155.3%，约下降 25.0%。这是短时配对采样，不等于整局功耗测量；当时另有一个与项目无关的 Node 服务占满一个 CPU 核。

改后完整统一回归通过：Code Analyzer 零问题，烟雾测试、连续序章和四条输入旅程全部通过。强制绘制五段为 80.6 / 109.5 / 77.5 / 93.7 / 152.6 FPS，最低 77.5 FPS；默认档和 1280×720 高画质档五段 50 Hz 定速完整刷新均为 49.6 FPS。真正的 `startGame('ValidationMode', true)` 主循环在北湖累计 9.5 秒、469 帧，为 49.2 FPS。

输入侧复查确认：窗口回调会把按键按下边沿写入 `pendingKeyPresses`，即使按下和松开都发生在两次读取之间，下一次快照仍能看到一次；游戏状态再把这次动作保留到下一次 60 Hz 物理步。`testInputMappings` 对这一短按路径有直接断言，四条完整输入旅程也通过。目标 Windows 的真实键盘硬件多键冲突仍只能到目标机验证。
