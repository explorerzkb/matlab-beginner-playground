# v22 Windows 证据闭环与 1 ms 试验

`runWindowsPlaytest` 现在为每局记录缩放、计划路线、实际路线、玩家二键位、唯一局号、两人共同操作确认、五段实际 FPS、通关状态，以及退出后的画面可读性和操作响应确认。`summarizeWindowsValidation` 逐项读取自动、交互和人工日志；只有三档缩放、至少三局、两条路线、两套键位、每段严格高于 40 FPS和三份人工确认全部齐全才报告 PASS。

解析器夹具覆盖两种状态：三档、三局、两路线和两键位的 FPS 日志全部齐全，但缺少人工确认时为 INCOMPLETE；加入三份元数据完全匹配的画面／操作确认后才为 PASS。当前真实 `windows-validation-results` 只有 Mac 日志，汇总为 0 / 3、INCOMPLETE，不会被误算成 Windows 证据。

本轮也试验了 1 ms JVM park。默认档五段定速最低从 v21 的 49.6 FPS 降到 47.2 FPS，同样时点的 8 次短时进程 CPU 采样也没有改善，因此该试验已撤销，最终代码仍使用已验证的 0.25 ms。恢复后完整统一回归通过：Code Analyzer 零问题，烟雾测试、连续序章和四条输入旅程通过；强制绘制五段为 80.1 / 103.2 / 74.2 / 95.5 / 147.9 FPS，最低 74.2 FPS，50 Hz 定速完整刷新五段均为 49.6 FPS。

这些仍是开发 Mac 证据。目标 Windows 的真实日志、两名真人判断与三档缩放尚未产生。

最终待验收包在全新目录解压后通过统一回归：强制绘制五段为 79.4 / 104.5 / 76.2 / 92.8 / 150.0 FPS，最低 76.2 FPS；默认档与高画质档五段定速刷新均为 49.6 FPS。包内汇总器面对空的 Windows 结果目录正确报告 0 / 3、INCOMPLETE。包包含 134 个项目文件和 1 份清单，共 135 项、27,275,412 字节；清单与当前工作树 0 差异，SHA-256 为 `6d6f9e6e6fbb777695a373fb68f15f4b93939f4a440c8db3127ad101a4a22a79`。
