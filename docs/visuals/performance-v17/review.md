# v17 性能与画面复核

日期：2026-09-10

状态：开发 Mac 的最终代码统一验收通过；目标 Windows 真人验收待做。

## 本轮取舍

- 默认画质保持 960×540，普通背景采样步长 6，校园网页采样步长 2，没有继续降低分辨率或纹理档位。
- 汽车和行人的物理、碰撞、推挤状态仍逐个计算，只把显示对象从 15 个合并为 6 个。
- 相同分辨率的冰红茶纹理只解码和描边一次；校园终段背景与校车仅在飞行落地后的独立场景创建。
- 尝试过按镜头懒创建校园网、交通和自行车对象。首帧世界层可从 220 个进一步降到 178 个对象，但移动中出现约 0.88 / 0.34 / 0.21 秒的一次性停顿，因此该方案已撤销。当前在玩家获得控制前预建全部飞行前交互。
- 删除对不可见坐标轴工具栏的主动访问后，按真实游戏的无菜单、无工具栏窗口测，冷首帧约 2.98 秒、共 270 个图形对象，世界层 220 个对象；没有改变画面内容。

## 最终代码统一验收

- Code Analyzer：0 个问题。
- 完整烟雾测试、连续序章和四条从出生点开始的输入旅程：全部通过。
- 强制逐帧：北湖 76.8、校园网／短跑 98.7、交通 65.4、自行车 89.6、校车 137.4 FPS；最低 65.4 FPS。
- 随后两次完整性能复测的全局最低为 62.1 和 82.1 FPS；三次最终代码检查均超过 40 FPS。
- 测试期间开发 Mac 上另一个孤立 Node 服务仍持续占满约一个 CPU 核。
- 方法：每段预热 30 帧，再对 120 帧逐帧执行 `drawnow`；比交互循环的 `drawnow limitrate` 更保守。
- 最新 Windows ZIP 在开发 Mac 的全新临时目录中独立解压后，125 个项目文件逐一哈希无差异；包内统一验收五段为 77.7 / 100.5 / 76.1 / 91.9 / 141.0 FPS，最低 76.1 FPS，其余检查也全部通过。
