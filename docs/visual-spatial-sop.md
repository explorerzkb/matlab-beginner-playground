# 视觉与空间合理性 SOP

更新日期：2026-09-03

本流程适用于目标效果图、关卡背景、灰盒布局、正式素材和后续二维／三维建模。它解决的不是“画得精不精致”，而是画面是否来自当前项目证据、物体是否落在合理位置、玩家是否能理解真实背景与可玩空间的关系。

## 1. 强制执行路径

视觉任务开始前，执行者必须按顺序完成以下步骤：

1. 读取 `current-project-state.md`、`game-spec-v1.md` 和 `implementation-plan.md`，确认当前场景及冻结要求；
2. 读取本 SOP；现实校园场景继续读取 `assets/reference/README.md` 和对应场景的索引；
3. **实际打开并目视检查**索引指定的地图、拓扑图和原始照片，不能只读取文件名、索引摘要或文字描述；
4. 填写或复核一张空间卡，先确定入口、出口、主地标、岸线、道路、承重点和不可确认项；
5. 先做不带装饰的空间骨架，标出前景可碰撞层、中景关系层和远景识别层；
6. 再生成、绘制或建模；完成后把结果与证据并排检查，并记录通过项、失败项和待核对项；
7. 未通过本 SOP 的图只能标为“探索稿”或“视觉预演”，不得称为最终效果、空间依据或运行时素材。

“实际打开”是指看到图片像素并观察其中的结构关系。仅知道某个文件存在、仅读到索引里的说明、或让另一个 Agent 口头转述，都不算完成。

## 2. 每次必须留下的证据

在 `docs/visuals/` 下为重要场景保留提示词或设计说明，并记录：

- 实际打开过的文件路径；
- 每份材料分别证明了什么，不能证明什么；
- 入口、出口、岸线、支撑、道路和地标的当前判断；
- 哪些空间关系是真实依据，哪些是为玩法加入的虚构；
- 最终检查结果和仍未解决的问题。

对于现实校园场景，最低证据组合是“一份地图或拓扑 + 一份能看清结构落点的照片 + 一份能看清人或动物尺度的照片”。如果索引明确列出更多必看材料，以索引为准。

## 3. 空间骨架先于美术

一张关卡图至少分成三层：

1. **前景可玩层**：角色、绳、鹅、平台、坑、检查点与出口；每个可站立面必须有连续、明确的碰撞边缘；
2. **中景关系层**：湖岸、道路、桥的落点、台阶、栏杆、桥墩或其他支撑，负责解释物体为什么在那里；
3. **远景识别层**：北湖红桥、树列、校园建筑等识别锚点，不承担碰撞时必须明显弱于前景。

真实背景和虚构玩法可以同时存在，但必须让玩家看得出哪一层可站、哪一层只是远景。不能因为横版玩法需要平台，就把真实桥梁、道路和湖岸拼成一个看似真实、实际无支撑的空间。

## 4. 图片与模型合理性检查

每张重要画面逐项检查：

- **接地与承重**：桥、栈道、平台、旗杆、建筑和树是否有岸端、地基、桥墩、悬挂点或其他可解释的支撑；除非规格明确要求超现实漂浮，否则不得悬空；
- **入口与出口**：桥或道路从哪里进入、通往哪里；画面裁切若隐藏一端，另一端和主要承重关系仍应成立；
- **岸线与水面**：水陆边界连续，桥面与水面高度、倒影、桥墩入水位置一致；不得把桥面直接贴在水面上；
- **尺度与透视**：人物、鹅、栏杆、桥、道路和建筑的相对尺寸不互相打架；同一层的透视、光向和阴影一致；
- **玩法可读性**：可碰撞边缘、危险区、检查点和出口在三秒内可辨认；装饰不得伪装成平台；
- **校园特征**：至少有一个由真实材料支持的北理识别锚点，不能只用通用校园、通用石桥或通用科技曲线替代；
- **证据边界**：照片没有证明的邻接、桥端或路线要标为未知，不能凭“看起来顺”补成校园事实；
- **媒介一致性**：真实截图、照片纹理和漫画场景混用时，要有明确边框、阴影或材质差异，使“异质界面闯入世界”是有意设计，而不是贴图事故。

出现以下任一情况即不通过：主要桥梁没有可解释的落点或支撑；现实地标被错误拼接；背景平台与可玩平台无法区分；角色或关键机关被遮挡；为了画面热闹加入规格外地点；真实界面被生成模型改写到无法辨认。

## 5. 校园网页面专项规则

第二关使用三张已经实际检查的真实界面截图：空白登录页、Chrome 超时页和登录成功页。它们不交给生成模型重画，也不使用 MATLAB 图元逐字仿制主体页面。

三张截图必须映射到同一个固定世界矩形。页面是一张嵌入世界的平面，不是全屏 UI：切换内容时不得移动、缩放、淡化或隐藏外框，摄像机也不得锁在页面中心。角色继续向右后，页面只因世界坐标自然离开画面。

第一次登录时直接显示完整 Chrome 超时页，同时撤掉网页承托使角色坠落；复位后恢复登录页。第二次双人登录先在原地显示短加载动画，再直接显示成功页。成功页中未经明确授权的 IP、流量、时长和余额必须在运行时副本中清除，用离线占位替代；当前只有学号 `1120250036`得到用户明确授权。

页面不是可操作登录窗口：不获取文本焦点、不收集真实密码、不打开浏览器、不访问校园网。进入运行时目录前和发布前各做一次目视隐私检查；碰撞继续由独立简单矩形承担。

## 6. 角色专项规则

两名角色是完整梨形身体，不画永久可见的腿，不加叶子或叶柄，也不套用人形跑步循环。移动通过整体轻微倾斜、挤压与拉伸、短距离弹跳、落地回弹、地面阴影和表情变化表达；这些视觉变化不能改变碰撞体。

角色需要保留真实梨的上窄下圆轮廓、柔和体积和极少量果皮浅坑／颗粒质感，同时保持简洁可爱。两人只用绿色与奶油白配色和轻微品种轮廓差异区分，不再使用胸前圆／菱形标记；体型、碰撞体和能力完全相同。绳连接身体侧下方的小连接环，不依赖腰带或四肢动作。
