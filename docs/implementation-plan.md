# 首版实现计划

更新日期：2026-09-03

本文把 [`game-spec-v1.md`](game-spec-v1.md) 转换成开发顺序。每个阶段只有通过最低验证后才进入下一阶段；普通实现细节可以在阶段内自主调整，但不能改变已冻结玩法。

文件名可以在实现中小幅调整，但职责边界不能消失。`startGame.m`只负责定位项目根目录、添加必要路径、读取配置并启动游戏；它不能逐渐膨胀成包含全部逻辑的巨型脚本。

## 2. 状态与数据流

游戏统一使用一个结构体保存动态状态：

```text
输入回调更新按键集合
        ↓
固定时间步读取输入
        ↓
更新两名角色速度与位置
        ↓
处理地面碰撞和普通绳约束
        ↓
关卡系统更新机关、检查点和完成条件
        ↓
渲染层只把最新状态画出来
        ↓
轨迹采样写入结算数据
```

配置、关卡数据和资源路径是只读输入；物理状态、关卡状态、统计和输入状态分区保存。渲染对象句柄与物理数据分开，避免把屏幕像素位置当成游戏世界坐标。

## 3. 运行循环

- 使用单个 `figure`，键盘按下和释放回调只更新按键状态，不直接移动角色；
- 主循环使用固定物理步长，目标每秒 60 次；帧间隔过大时最多补做有限次数的物理子步，避免补帧失控；
- 正常模式约每两次物理更新渲染一次，目标约 30 FPS；低配模式单独使用约 20 FPS；
- 进入关卡时创建图形对象，运行中只修改位置、数据和可见性，不在每帧删除重建；
- 关闭窗口、按退出或发生未处理错误时，统一停止循环、清除回调和音频，并恢复 MATLAB 状态；
- 游戏循环中不读盘、不解码图片或音频、不执行符号求解，也不访问网络。

## 4. 阶段门

凡是产生目标效果图、关卡背景、正式素材或空间模型，先执行 [`visual-spatial-sop.md`](visual-spatial-sop.md)。视觉阶段门不是阶段 4 才临时补做：阶段 2 的第一关布局和阶段 3 的校园网卡片同样要留下证据。Agent 必须实际打开参考图并记录观察结果，不能以“已读索引”代替目视核对。

### 阶段 0：骨架和窗口生命周期

交付：入口文件、三类集中配置、空白游戏窗口、暂停／退出、错误清理、Windows 启动文件占位说明。

最低验证：从任意当前目录运行入口都能找到项目根目录；窗口可正常关闭；关闭后命令窗口没有持续循环或残留回调。

### 阶段 1：双人灰盒

交付：两个几何角色、双键盘状态、地面、重力、跑跳、简单碰撞、普通绳、检查点和统计。

最低验证：连续运行十分钟不出现数值爆炸；两人可以互相拖回并完成一次摆荡；重置后状态干净；物理结果不随渲染帧率明显改变。

如果灰盒中的绳持续让一方失去控制，优先调绳长、拉力上限、阻尼、摩擦和关卡宽度，不先增加新技能。

### 阶段 2：第一关竖切

“竖切”指从进入、游玩、失败重试到过关全部走通的短版本。只实现北湖动物关，先用程序绘制的简化背景和几何鹅。

开始布局前：实际打开北湖索引要求的地图、拓扑、航拍、红桥、道路和动物照片，复核空间卡。灰盒也要区分真实岸线／远景地标和虚构可玩平台。

最低验证：未读说明的两位试玩者能完成本关，并能说清绳的作用；鹅的行为被理解为移动边界而不是敌人；红桥至少有一个可信岸端及支撑逻辑，且不会被误认为前景可踩平台。

### 阶段 3：其余三个关卡和结算

按校园网 → 艾比特 → 任务风暴顺序实现，每次只增加该关所需的新机关。最后接入轨迹采样、辅助曲线和结算。

校园网登录页不重画：把经过两次隐私检查的真实截图准备成运行时 PNG，由 MATLAB 作为图像显示，使用独立几何体做碰撞，不构造可输入表单。

最低验证：四关可以使用占位美术连续通关；检查点不会泄漏上一关状态；断网不影响流程；正常路线不要求主动失败；登录页文字和版式仍可辨认，但不会获取焦点或访问真实地址。

### 阶段 4：正式视觉与音频

从 `assets/reference/` 提炼原创、轻量的运行时素材，输出到 `assets/game/`。优先角色轮廓、碰撞边界、平台可读性和校园识别锚点，再处理装饰。

角色正式动画不制作腿部循环：用梨身倾斜、挤压、弹跳、回弹、阴影和表情状态表现动作。背景制作前先完成空间骨架，桥梁、栈道和平台必须有可信落点或支撑。

灰盒中的纯色块、少量圆形树和文字地名只用于验证，不是正式美术。正式校园场景即使走极简路线，也要补足可读的建筑结构节奏、门窗／栏杆、道路铺装、绿化层次、校园导视和有证据的北理锚点；观众应能在遮住关卡标题后仍判断这是校园，而不是抽象平台关卡。

最低验证：每个重要场景都有 `docs/visuals/` 检查记录并通过空间合理性硬检查；学校元素的细节密度和识别锚点通过逐关截图复核，不能仅靠 HUD 文字成立；替换素材后碰撞位置没有变化；不同窗口比例下文字和操作区域清楚；无腿角色的移动和受力状态可辨认；关闭音频仍可完整游玩。

### 阶段 5：Windows 实机验收

在目标 Windows 11、MATLAB R2025b 电脑上记录：冷／热启动、主要按键组合、平均与低位帧率、125%／150% 缩放、中文或空格路径、音频、连续三局和关闭清理。

最低验证：满足 `game-spec-v1.md` 的完成标准，并把具体机器、MATLAB 更新版本、测试日期和失败项写回 `current-project-state.md`。

## 5. 优先级和牺牲顺序

P0：双人输入、跑跳、普通绳、碰撞、检查点、四关完整流程、结算、Windows 稳定性。

P1：正式角色与场景、关键音效、按键检测、低配档、轨迹辅助线。
P2：可选 Symbolic 序章效果、更丰富动画、R2020b 冒烟测试、独立 EXE 评估。

时间不足时依次牺牲：装饰粒子和背景动画 → 非关键音效 → 复杂角色帧 → Symbolic 实时求解 → R2020b 与独立打包。不能牺牲双人核心、四关因果、快速重试和 Windows 验收。

## 6. 明确不要优化

- 不建立通用游戏引擎、实体组件系统或复杂类继承；
- 不实现像素级碰撞、连续柔性绳、绳与地形缠绕、完整刚体或流体模拟；
- 不为未来未知关卡提前设计插件系统、脚本语言或在线内容系统；
- 不在首版加入设置账户、云存档、排行榜、遥测或联网更新；
- 不同时维护多套等价启动框架；
- 不让研究资料、历史存档或高分辨率原图进入运行时扫描路径。
- 不用生成模型重画真实校园网登录页，也不为无腿梨角色建立人形骨骼或步态系统；
- 不在没有桥端、桥墩、岸线和前后景说明的情况下直接精修校园场景。

## 7. 每次实现后的最小记录

每完成一个阶段，在 `current-project-state.md` 更新四项：实际完成、实际运行环境、执行过的验证、仍未通过的问题。只有执行过的命令和真实试玩可以写成验证证据；代码存在、语法看起来正确或硬件规格足够都不等于运行通过。视觉任务还必须记录实际打开的参考文件及其证明范围；索引存在、提示词完整或图片看起来精致都不等于空间检查通过。
